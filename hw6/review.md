# Ошибки в отчёте

| Функция | Ошибка | Пример | Серьёзность |
| --- | --- | --- | --- |
| read_orders | Файл закрыт до начала обхода генератора. | Файл anna,100: list(read_orders(path)) падает с ValueError: I/O operation on closed file. | Падение |
| totals_by_user | groupby собирает только соседние записи. Старая сумма затирается. | anna,100, bob,50, anna,700: у Анны 700 вместо 800. | Тихо неверный результат |
| has_large_orders | bool от генератора всегда даёт True. | Заказ на 100, порог 1000: True вместо False. | Тихо неверный результат |
| build_report | После подсчёта заказов генератор пуст. | Если починить чтение, заказы anna,1200, bob,50 дадут число 2, но суммы {}. | Тихо неверный результат |
| vip_over_limit | zip молча отбрасывает данные, если длины не совпали. | Клиенты anna, bob, kate, лимиты 500 и 10: Кейт пропущена без предупреждения. | Тихо неверный результат |
| last_orders | readlines() загружает весь файл. | В тесте на 100 002 строках нужно больше 1 МБ памяти ради двух последних строк. | Производительность |
| last_orders | При n=0 срез [-0:] берёт все строки. | Файл anna,100: получаем ['anna,100'] вместо []. | Тихо неверный результат |
| last_orders | Нет проверки отрицательного n. | Строки anna,100, bob,50, n=-1: получаем ['bob,50'] вместо ошибки. | Тихо неверный результат |

В исправленной версии yield стоит внутри with, суммы копятся в словаре,
а крупный заказ ищется через any. Отчёт считается за один проход.
deque(maxlen=n) хранит только последние n строк, включая пустые.
При n=0 возвращается [], при n<0 возникает ValueError.

Клиента без лимита пропускаю с предупреждением: без лимита нельзя проверить
превышение. Поэтому Кейт пропускается, а результат остаётся ['anna', 'bob'].
Если лимит есть, а клиента нет, вызываю ValueError.

В test_report.py есть тест на каждую ошибку и проверка отчёта целиком.
Все 9 тестов проходят на report_fixed.py и падают на report.py.
